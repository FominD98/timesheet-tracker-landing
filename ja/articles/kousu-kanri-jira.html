工数管理を自動化する方法（Jira）

工数の数え方とJiraの作業ログの基本を押さえたうえで、「記録」と「割り当て」を切り分けて、毎週の工数入力を確認だけの作業に変える方法を解説します。

著者：AI Timesheet team · 2026年10月29日 · 約12分で読めます
要点
  • 工数は作業量を「人数×時間」で表したもの（人時・人日・人月）。IT現場の工数管理は、タスクごとの実績工数を記録し、見積もりと比べる予実管理が中心です。
  • Jiraでは作業ログが実績工数の記録単位です。課題ごと・日ごとに入力するため、手作業だと週末にまとめて思い出すことになり、精度が落ちます。
  • 自動化のコツは「記録」と「割り当て」を分けること。PCでの作業を自動で記録し、課題キーで照合し、迷う部分だけを人が確認します。
  • 工数管理と勤怠管理は別物です。工数管理ツールは出退勤や労働時間の公式な記録の代わりにはなりません。

工数とは？ 工数管理の基本

工数とは、ある作業を終えるのに必要な作業量を「人数×時間」で表した値です。単位には人時（にんじ）、人日（にんにち）、人月（にんげつ）が使われます。たとえば2人で3日かかる作業は6人日、1人で10時間かかる作業は10人時です。人日を時間に換算するときの「1人日＝何時間か」は会社や契約によって異なり、8時間とする現場が多いものの、7.5時間などで計算する組織もあります。

システム開発の工数管理では、主に次の2つの値を扱います。

  • 見積工数（予定工数）：着手前に「この課題には何時間かかるか」を見積もった値
  • 実績工数：実際にかかった時間を記録した値

この2つを比べるのが予実管理です。実績工数が正確に記録されていれば、見積もりの精度が上がり、プロジェクト別の原価や採算が見え、特定の人やチームへの負荷の偏りにも早く気づけます。準委任契約やSESでは、月ごとの稼働時間を報告し、契約で定めた精算幅（例：月140〜180時間）と照らし合わせることもあります。逆に言えば、実績工数が「だいたい」で入力されていると、これらはすべて意味を失います。

工数管理と勤怠管理の違い

「工数管理」で検索すると勤怠管理システムも多く出てきますが、両者は目的が違います。混同すると、どちらの記録も中途半端になりがちです。

観点工数管理勤怠管理
記録するものどのタスク・プロジェクトに何時間使ったか出勤・退勤・休憩・労働時間
主な目的見積もり、原価管理、進捗・負荷の把握労働時間の把握、給与計算、法令対応
主な利用者本人、プロジェクトマネージャー人事・労務、管理者
よく使う場所Jira、Redmine、Backlog、Excelの工数管理表勤怠管理システム、タイムカード

労働時間の把握は会社の義務であり、勤怠管理システムなど会社が定めた方法で行うものです。一方、工数は1日の勤務時間をタスクにどう配分したかの記録です。会議、休憩、雑務などがあるため、勤怠の合計と工数の合計は通常一致しません。この差を「その他」で埋めるのではなく、後述する間接作業用の課題に記録するのが、正確な工数管理の第一歩です。

Jiraで工数を記録するしくみ（作業ログ）

Jiraには標準でタイムトラッキング機能があり、課題ごとに次の値を持てます。

  • 初期見積もり（Original estimate）：見積工数
  • 残り時間の見積もり（Remaining estimate）：あと何時間かかるか
  • 作業ログ（Worklog）：誰が、いつ、何時間、何をしたかの記録。合計が実績工数になります

作業ログは課題画面から入力します（英語UIでは Log work）。時間は 1w 2d 3h 30m のような書式で入力でき、初期設定では1日＝8時間、1週＝5日として換算されます。この換算は管理者が変更できるので、自社の「1人日」に合わせて設定されているか一度確認しておきましょう。プロジェクトでタイムトラッキングが有効になっていないと入力欄が表示されないため、その場合は管理者に依頼します。

課題画面以外にも、作業ログを登録する方法があります。

  • スマートコミット：Bitbucket・GitHub・GitLabなどと連携していれば、コミットメッセージに ABC-123 #time 1h 30m ログイン画面のバリデーション修正 と書くだけで作業ログが登録されます。
  • REST API：Jira Cloud では POST /rest/api/3/issue/{課題キー}/worklog、Jira Server / Data Center では /rest/api/2/ の同じエンドポイントで登録できます。自作スクリプトでの一括登録に使われます。

自分の今週の工数を確認するには、JQLで worklogAuthor = currentUser() AND worklogDate >= startOfWeek() と検索すると、今週作業ログを付けた課題の一覧が得られます。Jiraでの作業時間の記録方法をさらに詳しく知りたい方は、英語のガイド「How to log time in Jira」もご覧ください。

手作業の工数入力がつらい理由

Jiraの作業ログは「課題×日」単位です。5つの課題を並行して進めた1週間なら、最大で25件近い入力が必要になります。しかも実際の1日は、計画どおりには進みません。

  • 割り込みが多い：Slackでの質問、急ぎのコードレビュー、障害の一次対応。どれも短いけれど、積み重なると数時間になります。
  • 思い出すのに時間がかかる：金曜の夕方に火曜日の作業を再現するには、チャット履歴、ブラウザーの履歴、コミットログを見返す必要があります。
  • タイマーが続かない：開始と停止の押し忘れ、切り替えのたびの操作が負担になり、結局あとから手で直すことになります。
  • 丸めて精度が落ちる：面倒なので「開発作業 8h」とまとめて入力すると、見積もりとの比較ができなくなります。

つまり問題は入力の手間そのものより、「何に何時間使ったか」を後から復元する作業にあります。ここを自動化できれば、工数入力は確認だけの作業になります。

工数管理の方法を比較：Excel・タイマー・工数管理ツール・自動記録

方法入力の手間精度Jiraとの関係向いているケース
Excelの工数管理表大きい（すべて手入力）記憶に依存二重管理になりやすいJiraを使わない小規模チーム
タイマー型タイムトラッカー中（開始・停止の操作）押し忘れで欠ける連携機能による作業の切り替えが少ない人
Jiraアドオン（Tempo Timesheets など）中（入力は基本的に手動、提案機能あり）記憶に依存Jira内で完結チーム全体の工数を管理者が集計したい場合
デスクトップの自動記録型ツール小（確認と修正のみ）実際の作業記録にもとづく作業ログとして送信割り込みが多く、Jiraに工数を入力する個人

どれか1つが常に正解というわけではありません。チームとして集計・承認のワークフローが必要ならJiraアドオン、個人の入力負担を減らしたいなら自動記録型、というように目的で選ぶのが現実的です。両方を組み合わせることもできます。

Jiraの工数入力を自動化する5つのステップ

1. 課題キーを作業の「痕跡」に残す

自動化の精度は、作業の痕跡に課題キーがどれだけ含まれているかで決まります。ブランチ名を feature/ABC-123-login のように付ける、コミットメッセージやプルリクエストのタイトルの先頭に ABC-123 を入れる、会議の予定やConfluenceのページ名にも課題キーを書く。これだけで、ウィンドウタイトルから課題を特定できる時間が大きく増えます。

2. 間接作業用の課題を用意する

「定例・会議」「問い合わせ対応」「障害対応」「レビュー」など、特定の開発課題に属さない作業の受け皿を、プロジェクトごとに課題として作っておきます。受け皿がないと、こうした時間は「その他」に丸められるか、記録されずに消えてしまいます。

3. PCでの作業を自動で記録する

アクティブなアプリ、ウィンドウタイトル、ブラウザーのドメイン、離席時間をバックグラウンドで記録するツールを使えば、タイマーの操作は不要になります。記録の段階では「どの課題か」を決めなくてかまいません。後で振り返るための材料をそろえておくことが目的です。

4. 1日の終わりに確認して確定する

課題キーが含まれる時間は自動で課題に割り当て、残りだけを確認します。毎日5分の確認なら記憶が新しいうちに判断でき、金曜日にまとめて1時間かけるよりずっと正確です。迷う部分だけを判断すれば済むようにしておくのがポイントです。

5. Jiraに送信し、週単位で見直す

確定した工数を作業ログとしてJiraに送信します。週に一度、前述のJQLや集計画面で見積もりと実績を見比べると、見積もりのずれに早く気づけます。送信をやり直したときに作業ログが二重に登録されないかも、ツール選びの重要なポイントです。

丸めのルールはチームで決める：Jiraは分単位で入力できますが、15分単位や30分単位に丸めるかどうかはチームの運用次第です。自動記録を使う場合も、最終的な値はチームのルールに合わせて確認してから送信しましょう。

Timesheet Trackerでの自動化の例

Timesheet Trackerは、上の3〜5のステップをまとめて引き受けるWindowsアプリです。Microsoft Storeでは「工数管理・タイムトラッカー - Jira用AI」として公開しています。

  1. 通知領域に常駐し、アクティブなプログラム、ウィンドウタイトル、Webサイトのドメイン、離席や画面ロックの時間を記録します。データはPCに保存されます。
  2. ウィンドウタイトルに BILL-142 のような課題キーがあれば、その時間はAIを使わずにPC上でその課題に割り当てられます。
  3. 1日の終わりに「この日を仕分け」を押すと、残りの時間をAIがJiraのタスクに割り当て、タスクごとに作業ログのテキストを1つ下書きします。
  4. タイムラインを確認し、必要なら「タスクを変更」や「業務外」で直して、「この日を確定」します。
  5. 「Jiraに送信」で Jira Cloud または Jira Server / Data Center に作業ログを送信します。再送しても重複しません。「CSVをエクスポート」でExcelの工数管理表に取り込むこともできます。

AIに送られるのは「この日を仕分け」を押したときだけで、内容はマスク済みのウィンドウタイトル、プログラム名、ドメイン、時間、Jiraのタスクです。スクリーンショット、キー入力、ページの内容は記録も送信もしません。AIを使いたくない場合は「AIなしで使用」を選べば、課題キーによる照合と手動の割り当てだけで使えます。

工数管理ツールを選ぶときのチェックリスト

  • Jiraとの連携：Jira Cloud と Jira Server / Data Center のどちらに対応しているか。作業ログとして直接書き込めるか。
  • 重複の防止：送信に失敗して再送したとき、作業ログが二重に登録されないか。
  • 記録する範囲：スクリーンショットやキー入力を記録するか。何がPCの外に送られるか。
  • 誰のためのツールか：個人の工数入力を助けるものか、管理者が従業員を監視するものか。業務PCに導入する前に、社内規程や情報システム部門の方針も確認しましょう。
  • エクスポート：CSVやExcelで書き出して、既存の工数管理表や社内システムに取り込めるか。
  • 料金体系：ユーザー単位の課金か、個人で契約できるか。無料で試せる期間があるか。

よくある質問

工数と作業時間は何が違いますか？

作業時間は1人が実際に作業した時間、工数はその作業に必要な量を「人数×時間」で表したものです。1人で作業した場合は同じ値になりますが、工数は人日・人月のように複数人の作業量を合算して見積もりや原価計算に使います。

Jiraの作業ログは何分単位で入力すべきですか？

Jira自体は分単位で入力できます。15分単位や30分単位などの丸めはチームのルールで決めるのが一般的です。細かすぎると入力の負担が増え、粗すぎると予実管理に使えないので、見積もりの粒度に合わせるのがおすすめです。

工数管理ツールを入れると、会社に作業を監視されますか？

ツールによります。スクリーンショットやキー入力を管理者に送る監視型のツールもあります。Timesheet Trackerは個人用で、記録はPCに保存され、スクリーンショット、キー入力の記録、上司へのレポートはありません。Jiraに送られるのは本人が確定した作業ログだけです。

Excelの工数管理表と併用できますか？

できます。Timesheet Trackerは確定した工数をCSVで書き出せるので、既存のExcelの工数管理表や社内システムに取り込めます。Excel（XLSX）形式への直接の書き出しは今後対応予定です。

工数入力を自動化すると、勤怠の記録も不要になりますか？

なりません。工数管理はタスクごとの作業時間の配分を記録するもので、出退勤や労働時間の記録は会社の勤怠管理システムで行います。両者は目的も根拠も異なるため、別々に運用してください。
